Maintenance

Declarative package lists, a global gitconfig with delta diffs, a one-command updater, a worktree-friendly node_modules sweeper, a line-count ranker that exposes refactor candidates, and a background LaunchAgent that quietly sweeps ~/Downloads onto the NAS. Keeps the system reproducible, current, and tidy without thought.

bin/clean-node-modules

Reclaim disk space across your repo and its git worktrees. Scans $PWD recursively, lists every top-level node_modules with its size, then deletes them after a single confirmation. Nested node_modules inside another node_modules are pruned from the walk so the scan stays fast. Symlinked to ~/.local/bin/clean-node-modules so it's on your $PATH in zsh and fish.

Interactive — recommended

Run from the directory you want to scan — the tool always uses $PWD as the root, never your home directory. npm install / bun install rebuilds node_modules from the existing lockfile, so deleting is safe on any committed project.

bin/bigfiles

Refactor radar. Ranks every source file under $PWD by line count, skipping the noise — node_modules, .git, build, dist, out, target, .next, .nuxt, .turbo, .expo, .yarn, .venv, __pycache__, .gradle, Pods, DerivedData, .dart_tool, vendor, lock files, minified bundles, source maps — so the ranking reflects code you actually wrote. Useful when an AI-assisted codebase grows quietly and a single file drifts past four-figure line counts. Symlinked to ~/.local/bin/bigfiles so it's on $PATH in zsh and bash; a thin fish wrapper at ~/.config/fish/functions/bigfiles.fish exposes it as a fish function too.

bin/sort-downloads

Background auto-sorter for ~/Downloads and ~/Pictures/Screenshots. A launchd LaunchAgent watches both folders in real time; whenever a file lands, it's classified (or force-routed) and moved to a matching top-level folder on the TrueNAS share at /Volumes/media/. The local folders stay empty, the laptop's SSD stays free, and everything is one SMB-mount away on the NAS.

Symlinked to ~/.local/bin/sort-downloads; runs whenever you want via the CLI, but the LaunchAgent at ~/Library/LaunchAgents/com.prometheus.sort-downloads.plist is what makes it automatic. Both are installed by install.sh.

Sources

Defined by the SOURCES array at the top of the script as "path|override" pairs. Empty override → classify each file by extension/name. Non-empty override → every file in that folder lands in /Volumes/media/<override>/ with no classification.

~/Downloads(none)Classify each file by extension and screenshot-name pattern
~/Pictures/ScreenshotsScreenshotsEvery file routes to /Volumes/media/Screenshots/ — matches macOS's default screenshot location, so ⌘⇧3 / ⌘⇧4 shots auto-drain to the NAS

Safety guards

The script is paranoid because mv on the wrong file is hard to undo:

  • NAS must be mounted. Refuses to run unless /Volumes/media appears in mount output — a stub folder won't fool it.
  • No partial downloads. Skips files ending in .crdownload, .download, .part, .tmp, .aria2, .opdownload, plus all dotfiles.
  • Settle delay. Files modified in the last 30 seconds are left alone — protects against grabbing a file mid-write.
  • Top level only. Subfolders of either source are never touched. Directories at the root are skipped.
  • No collisions. If foo.png already exists on the NAS, the new one becomes foo (1).png, then foo (2).png, etc.
  • Cross-volume mv is copy-then-unlink. If the SMB link drops mid-transfer, the source stays in its original folder — no data loss.
  • Single-instance lock. Atomic mkdir /tmp/sort-downloads.lock prevents concurrent runs when launchd fires a burst of WatchPaths events.

The LaunchAgent

Lives at dotfiles/launchd/com.prometheus.sort-downloads.plist. It's an Agent, not a Daemon, on purpose — root daemons can't see user-mounted SMB shares, so the worker must run as the user. The plist uses __HOME__ as a placeholder; install.sh substitutes $HOME at install time so the repo stays portable.

KeyValue
WatchPaths~/Downloads + ~/Pictures/Screenshots — any change to either fires the script
ThrottleInterval30s — debounces bursts; also gives partial downloads time to finish
RunAtLoadtrue — sweeps anything already in either folder on login
StandardOutPath / StandardErrorPath~/.sort-download/sort-downloads.log
Manual install (install.sh does this for you)
mkdir -p ~/Library/LaunchAgents
sed "s|__HOME__|$HOME|g" ~/dotfiles/launchd/com.prometheus.sort-downloads.plist \
  > ~/Library/LaunchAgents/com.prometheus.sort-downloads.plist
launchctl load ~/Library/LaunchAgents/com.prometheus.sort-downloads.plist
Check it's loaded
launchctl list | grep sort-downloads

A line like - 0 com.prometheus.sort-downloads means loaded and waiting. The middle column is the exit code of the last run.

Force a sweep right now
launchctl start com.prometheus.sort-downloads
Uninstall
launchctl unload ~/Library/LaunchAgents/com.prometheus.sort-downloads.plist
rm ~/Library/LaunchAgents/com.prometheus.sort-downloads.plist

What happens if the NAS is offline?

Nothing destructive. The script logs NAS not mounted at /Volumes/media — skipping sweep and exits 0. Files pile up in ~/Downloads and ~/Pictures/Screenshots until the share is mounted again; the next file event re-fires the watcher and everything drains in one pass. The watcher does not wake on its own when the mount returns — drop one new file into either source folder to kick it, or run launchctl start com.prometheus.sort-downloads.

Adding more sources

Edit the SOURCES array at the top of bin/sort-downloads — each entry is "path|override". Then add the same path to the plist's WatchPaths array so launchd actually fires on changes to it.

Example — also drain ~/Desktop
# bin/sort-downloads
SOURCES=(
  "$HOME/Downloads|"
  "$HOME/Pictures/Screenshots|Screenshots"
  "$HOME/Desktop|"             # classify each file
)

Want a different mount or no catch-all bucket? NAS respects the env var SORT_DOWNLOADS_DST so you can override without forking. To skip the catch-all, drop the *) echo "Other" branch from the classify() function.
